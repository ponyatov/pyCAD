## Протокол обмена бизнес-командами с верхним уровнем

взаимодействие верхнего уровня с аппаратом выполняется через передачу сообщений по протоколу [[Сетевые настройки#MQTT|MQTT]] в следующие топики:

## Топики MQTT

В рамках запуска MVP структура топиков была сведена к следующей:

- `Machine/{ID}/Config/Sections` - хранит конфигурацию секций
- `Machine/{ID}/Command` - топик в который ВУ пишет команду
- `Machine/{ID}/Response` - топик в который НУ пишет ответы
- `Machine/{ID}/HID/QR` - топик в который НУ пишет ввод от периферии
- `Machine/{ID}/HID/RFID` - топик в который НУ пишет ввод от периферии

### Response

- **ответы от НУ по статусам обработки [Transaction](#Transaction)-запроса**
- ответ приходит отдельным сообщением для каждой ячейки

### Command

- **запрос на выдачу ТМЦ от BI** приходит через `Machine/{ID}/`
- передаётся список ячеек на выдачу

## Предлагаемые команды

- [Transaction](#Transaction) – запрос на выдачу ТМЦ из указанных ячеек;

Не реализовано:

- `GetAll` – выдача ТМЦ, открытие всех ячеек (массив Cells в данном случае не учитывается);
- `SetItem` – загрузка ТМЦ в указанные ячейки (только для постоматной секции)
- `SetAll` – загрузка ТМЦ во все ячейки по загруженной конфигурации;
- `GetStatus` – получение статуса аппарата;
- `Reboot` – перезагрузка аппарата;
- `Halt` – выключение аппарата;
- `Maintenance` – перевод аппарата в режим обслуживания.
- `SetConfig` – загрузка конфигурационного файла;
- ручное перемещение лифта: `LiftUp` / `LiftDown`
- `FlipUnlock` ручная разблокировка люка выдачи
- `LoadProfile` загрузка профиля выдачи на нижний уровень
- `RunProfile` выдача по ранее загруженному профилю

## Transaction

схема запроса:

```
Transaction
	ID : GUID         // уникальный идентификатор транзакции
	Timestamp : ts    // метка времени
	UserID : string   // уникальный идентификатор конечного пользователя
	Source = "HiLvl"  // идентификатор верхнего уровня
	Orders
		Target
			id   : GUID               // идентификатор аппарата
			name : string	          // имя аппарата
		Command  : enum Command       // имя команды
		Cells[]
```

```json
{
	"Transaction": {
		"ID": "36-symbol GUID",      // уникальный идентификатор транзакции
		"Timestamp": "Fri, 02 Feb 1996 08:04:05", // время запуска транзакции
		"UserID": "aa-bb-cc",	     // уникальный идентификатор пользователя
        "Source": "HiLvl",           // Источник сообщения - верхний уровень
		"Orders": [
			{
				"Target": {						// аппарат, которому предоставляется данная транзакция
					"id": "GUID",					// идентификатор аппарата
					"name": "Machine-1-spiral",	// имя аппарата
				},								 // выполнение транзакции
				"Command": "GetItem",				 // команда данной транзакции
				"Cells": [							 // набор ячеек, на которые распространяется указанная команда
					{				
						"row": 2,					 // строка
						"column": 5,				 // столбец
						"quantity": 3,				 // количество ТМЦ
						"itemID": "GUID"
					},
					{				
						"row": 2,
						"column": 6,
						"quantity": 1,
						"itemID": "GUID"
					},
					{				
						"row": 3,
						"column": 1,
						"quantity": 2,
						"itemID": "GUID"
					},
				]
			}...
		]
	}
}
```

В ответ по ходу выполнения операции НУ отправляет отдельно для каждой отработанной ячейки ответы следующего формата:

```json
{
	"Response": {
		"ID": "GUID",					 // уникальный идентификатор
		"ParentID": "Parent-GUID",			 // идентификатор транзакции, на которую отвечаем
		"Timestamp": "Fri, 10 Apr 2026 08:04:05",// время выполнения транзакции
		"Target": {						// аппарат, которому предоставляется данная транзакция
			"id": "GUID",					// идентификатор аппарата
			"name": "Machine-1-spiral",	// имя аппарата
		},
		"Cell": {
			"row": 2,				
			"column": 5,			
			"quantity": 3,			
			"itemID": "GUID"
		},
        "Result": "OK" | "FAIL"                       
    }
}
```

Если в выдаче было отказано (например из за открытой двери) или ошибка произошла на этапе передвижения лифта, то будет направлено только одно сообщение без поля `Cell`

## сообщения НУ -> BI

Для генерации сообщений с устройств нижнего уровня предлагается использовать такую-же конструкцию транзакции, например:

```json
{
	"Transaction": {
		"ID": "36fa-aabc-012d",					    // уникальный идентификатор транзакции
		"Timestamp": "Fri, 02 Feb 1996 11:17:55",   // время выполнения транзакции
		"User": {	},							    // пользователь пуст
        "Source": "Lo-level - {RFID | QR}",         // Источник сообщения - RFID
		"Target": {								    // аппарат, которому предоставляется данная транзакция
			"id": 0,							    // идентификатор аппарата
			"name": "Top level",				    // имя объекта назначения
			"type": "top level control",		    // тип объекта - управление на верхнем уровне
			"article": "12qw-5577-a7f8"			    // артикул аппарата
		},
		"Order": { { "type", "barcode" } },		    // Информация со считывателя			
	}
}
```
